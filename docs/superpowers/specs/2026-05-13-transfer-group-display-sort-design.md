# 转移分组标题展示排序设计

## 背景

主界面普通订阅分组支持点击列表标题排序。转移分组的列表来源不同：它由转移队列节点和未参与队列的候选节点组合而成，并且队列节点的顺序还承担故障转移和延迟转移的运行含义。

当前普通标题排序会调用普通节点排序逻辑，普通逻辑只面向 `ProfileItem.Subid` 所属节点写入 `ProfileEx.Sort`。转移分组列表则通过 `FailoverGroupManager` 读取队列候选并在 `ProfilesViewModel` 中把队列节点置顶。因此，直接复用普通排序不能完整表达转移分组的展示需求。

## 目标

- 未开启转移模式时，转移分组点击标题后按普通列表展示逻辑排序，但只改变当前 UI 展示顺序。
- 开启 `故障转移` 或 `延迟转移` 时，参与转移队列的节点固定在顶部，并保持队列运行顺序。
- 开启转移模式时，未参与转移队列的候选节点仍可按标题列排序，但始终位于队列节点下方。
- 从关闭切换到开启转移模式时，立即把参与转移队列的节点放到列表最上方。
- 从开启切回关闭时，不恢复开启前的普通排序快照，也不主动套用开启前或开启期间保存的标题排序；用户可在关闭状态下再次点击标题重新按普通列表排序。
- 标题排序只影响列表展示，不修改真实转移队列优先级。

## 非目标

- 不改变故障转移和延迟转移的核心运行顺序。
- 不把标题排序写入 `FailoverGroupItem.Sort`。
- 不改变节点加入、移出、拖拽调整转移队列的现有语义。
- 不修改代理模式、Tun、系统代理、路由、DNS、订阅、证书或核心更新策略。

## 行为规则

### 普通订阅分组

保持现有行为。用户点击标题后，继续按列排序普通节点，并写回普通列表使用的排序字段。

### 转移分组且未开启转移模式

按普通列表展示逻辑处理标题排序。此状态下转移队列没有参与运行，列表可以完整响应用户选择的列排序，不再强制把队列节点置顶。

这里的“普通列表展示逻辑”必须和现有普通分组标题排序的列比较规则保持一致，包括：

- `ConfigType`、`Remarks`、`Address`、`Port`、`Network`、`StreamSecurity`、`DelayVal`、`SpeedVal`、`SubRemarks`、`TodayDown`、`TodayUp`、`TotalDown`、`TotalUp` 的列映射以现有普通排序实现为准。
- 延迟和速度列按数值排序，缺少延迟或速度的节点沿用普通排序的末尾处理规则。
- 流量统计列按可比较的数值语义排序，不按 `Utils.HumanFy` 之后的展示文本做字典序排序；如果当前列表模型只保存展示文本，实施时必须补充原始统计数值或等价的可比较字段供排序使用。
- 如果现有普通排序中某个列名的比较字段和界面展示字段不完全一致，转移分组展示排序仍以现有普通排序行为为准，避免同一列在普通分组和转移分组中排序语义不同。

这里的“未开启转移模式”指当前选中的转移分组不是活动运行分组，或全局转移模式为 `Off`。用户在此状态下点击标题后，已加入转移队列的节点可以随普通列排序移动到列表后部。

### 活动转移分组且开启转移模式

当当前分组是活动转移分组，并且模式为 `Failover` 或 `LeastDelay` 时，列表分成两段展示：

1. 队列段：已加入转移队列的节点，保持转移运行顺序，不受标题排序影响。
2. 候选段：未加入转移队列的候选节点，响应标题排序。

两段之间的相对位置固定：队列段始终在候选段上方。

`Failover` 模式下，队列段按用户维护的 `FailoverGroupItem.Sort` 顺序展示。`LeastDelay` 模式下，队列段沿用现有运行态顺序，即延迟最低的可用节点可被放到运行态第一位。

### 模式切换

当用户从 `Off` 切换到 `Failover` 或 `LeastDelay` 时，当前活动转移分组立即重新分段：队列段放到最上方，候选段放到下方。即使用户此前在关闭状态下通过标题排序把队列节点排到了后面，开启后也必须重新突出队列节点。

当全局转移模式已经是 `Failover` 或 `LeastDelay`，用户把当前转移分组设为活动转移分组时，也必须立即重新分段并把队列段放到最上方。

当用户从 `Failover` 或 `LeastDelay` 切回 `Off` 时，不保存也不恢复开启前的普通排序快照。切回关闭模式本身只更新转移状态，不应因为此前保存过标题排序列而立即重新排序整个转移分组。列表可以保留最近一次分段展示结果，后续如果用户在关闭状态下再次点击标题，则重新按普通列表展示逻辑排序整个转移分组。

## 数据流

1. `ProfilesView` 捕获 `DataGrid.Sorting` 事件，继续把列名传给 `ProfilesViewModel.SortServer`。
2. `ProfilesViewModel.SortServer` 根据当前分组状态分流：
   - 普通分组：调用现有普通排序逻辑。
   - 转移分组未开启转移模式：用户点击标题时使用普通展示排序逻辑，排序只作用于当前组合列表展示，不写入普通节点排序字段。
   - 活动转移分组且开启转移模式：记录候选段展示排序列和方向，刷新列表。
3. 模式切换到 `Failover` 或 `LeastDelay`，或当前转移分组在开启模式下成为活动转移分组时，触发列表刷新，强制按队列段和候选段分段展示；模式切回 `Off` 时不主动应用已记录的标题排序，等待用户下一次标题点击。
4. `GetProfileItemsEx` 构建转移分组列表时根据模式决定最终排序：
   - 队列段固定使用 `FailoverGroupManager.GetQueueEntriesForMode` 得到的转移运行顺序。
   - 候选段按当前标题排序列和方向排序，列比较规则复用普通列表展示排序规则。
   - 流量统计列排序使用原始统计数值或等价可比较字段，展示层仍显示 `Utils.HumanFy` 结果。
5. 列表刷新后，选择状态尽量保留当前选中节点；无法保留时使用现有默认选择规则。

## 状态与持久化

普通订阅分组的排序保持现有持久化方式。

转移分组的标题排序作为 ViewModel 内存态保存，不写入数据库。这样能避免转移分组的组合列表展示排序影响节点原订阅分组排序，也能避免候选展示排序和真实转移队列顺序互相污染。

内存态排序应按转移分组 Id 记录，避免用户在一个转移分组点击标题后，切换到另一个转移分组时继承不相关的排序列和方向。

未开启转移模式时，转移分组复用普通列比较规则，但仍只在 UI 层重排当前组合列表，不调用普通分组的持久化排序入口。

不维护“开启转移模式前的列表顺序”快照。开启模式代表用户当前关注转移队列，因此切回关闭时无需恢复旧的普通排序位置。切回关闭时应把当前转移分组已记录的标题排序状态标记为未激活，暂停自动应用此前记录的标题排序；只有用户再次点击标题，才按关闭模式规则排序整个转移分组。

## 错误处理

- 列名为空或不支持时，不改变当前排序。
- 候选节点缺少延迟、速度或统计数据时，沿用普通排序的空值处理规则。
- 转移队列中引用的源节点不存在时，继续沿用现有 `FailoverGroupManager` 过滤行为。

## 测试计划

- 单元测试：转移分组关闭模式下，标题排序能按指定列重排列表，并且列比较规则与普通分组一致。
- 单元测试：`Failover` 模式下，队列节点保持 `P1/P2/P3` 顺序，候选节点按标题列排序并位于队列下方。
- 单元测试：`LeastDelay` 模式下，队列节点保持运行态顺序，候选节点按标题列排序并位于队列下方。
- 单元测试：关闭状态下先按标题把队列节点排到后部，切换到 `Failover` 或 `LeastDelay` 后队列节点重新置顶。
- 单元测试：全局转移模式已开启时，将当前转移分组设为活动分组后队列节点重新置顶。
- 单元测试：从开启模式切回 `Off` 不依赖开启前排序快照，也不主动套用此前保存的标题排序；用户再次点击标题后整个转移分组按普通展示排序。
- 单元测试：延迟、速度和流量统计列的排序处理与普通分组一致，包括缺少延迟或速度的节点位置。
- 单元测试：标题排序不修改 `FailoverGroupItem.Sort`，也不写入 `ProfileEx.Sort`。
- 手工验证：主界面切换普通分组、转移分组关闭、故障转移、延迟转移四种状态，点击备注、地址、延迟列确认展示符合预期。

## 代理安全影响评估

本设计只调整主界面转移分组列表的展示排序。真实代理运行顺序仍由 `FailoverGroupManager`、`FailoverGroupItem.Sort` 和延迟转移运行态排序决定。设计不修改代理模式、Tun、系统代理、路由规则、DNS、订阅、核心组件、Geo/SRS 数据、更新下载、证书、网络请求或本地监听端口，不应导致流量绕过代理、错误直连、DNS 泄漏、订阅泄漏、证书信任扩大、核心组件降级或安全更新缺失。
