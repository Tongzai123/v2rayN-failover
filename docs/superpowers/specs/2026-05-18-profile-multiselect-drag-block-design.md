# 主列表多选节点块拖拽设计

## 背景

Desktop 主界面的节点列表已经支持拖拽排序，也已经支持 `Ctrl` / `Shift` 多选。但当前拖拽排序链路只记录一个拖拽源节点：UI 层保存单个 `_dragSourceItem` 和 `_dragSourceIndexId`，拖拽浮层只渲染一行，避让动画只根据一个 `sourceIndex` 计算，`ProfilesViewModel.MoveServerTo` 和 `ConfigHandler.MoveServer` 也只移动一个节点。

因此，多选后拖拽只会移动其中一个节点。目标行为是：用户多选节点后，从已选节点中的任意一行开始拖拽，所有选中节点作为一个整体移动；如果选中节点不连续，落位后合并为连续块，并保持拖拽前的相对顺序。

## 用户可见行为

- 从未选中节点开始拖拽时，仍按现有单节点拖拽排序处理。
- 从已选节点开始拖拽时，如果当前选中数量大于 1，则拖拽整个选中集合。
- 非连续多选拖拽后，选中节点会合并成连续块。
- 批量移动时，源节点相对顺序保持不变。例如原列表中选中第 2、4、5 个节点，移动后这三个节点仍按 2、4、5 的相对顺序排列。
- 将块拖到自身覆盖范围内或等价位置时，不产生排序变更。这里的“自身覆盖范围”包含非连续源集合首个源行到最后一个源行之间的未选中行，例如选中第 2、4 行并释放到第 3 行时，应视为不变更。
- 拖拽完成后刷新列表，排序结果由 `ProfileEx.Sort` 或故障转移队列排序持久化。

## 范围

本次设计只覆盖 Avalonia Desktop 主界面 `ProfilesView.axaml.cs` 的节点列表拖拽排序。WPF 版已有不同拖拽入口，本次不扩展。订阅分组拖拽排序也不纳入本次改动。

## 推荐方案

采用“批量移动链路”方案，不循环调用现有单节点移动方法。

UI 层在鼠标按下时仍记录当前源行，同时准备一个拖拽源集合快照。进入实际拖拽时，如果源行属于 `ViewModel.SelectedProfiles` 且选中数量大于 1，则源集合取所有已选节点的 `IndexId`；否则源集合只包含当前源行。源集合按当前 `ViewModel.ProfileItems` 展示顺序排序，避免 `SelectedItems` 内部顺序影响最终结果。

ViewModel 增加批量移动入口，例如 `MoveServersTo(IReadOnlyList<string> sourceIndexIds, ProfileItemModel targetItem)`。这个方法负责区分普通分组与故障转移分组，并把源集合、目标节点、当前展示列表转换成可持久化的排序结果。

底层排序新增批量方法。普通分组中，先按当前列表顺序取出所有源节点，再从列表副本中移除这些源节点，计算目标节点在移除源节点后的插入位置，插入整个源块，最后统一重写所有相关节点的 `Sort`。这样可以避免逐个移动导致的索引漂移。

## 故障转移分组规则

故障转移分组需要保持现有安全边界：

- 当故障转移队列被置顶时，队列节点只能在队列区内移动，非队列节点只能在非队列区内移动。
- 批量源集合不能同时包含队列节点和非队列节点。
- 目标节点必须与批量源集合属于同一可移动区域。
- 队列区批量移动应更新 `FailoverGroupItem.Sort`，并在成功后继续执行现有的首位提升和状态刷新逻辑。
- 非队列区移动仍更新普通节点展示排序，不修改故障转移队列成员关系。

如果上述条件不满足，拖拽释放后不改变排序。

## 动画与浮层

现有 `ProfileDragDropAnimation.GetRowOffset` 只支持单个源行。需要新增块移动计算函数，输入源行索引集合、目标行索引和行高，输出每一行应移动的距离。

视觉上优先实现稳定清晰的块拖拽：

- 所有源行在拖拽期间作为原位透明占位。
- 非源行按块高度进行避让。
- 拖拽浮层可以显示多行堆叠；如果多行浮层实现复杂，可显示首行内容加选中数量提示，但不能影响排序结果。

动画计算应放在纯函数中，并用单元测试覆盖向上、向下、非连续源集合、自身范围内拖拽、无效输入等场景。

## 数据流

1. `ProfilesView` 在 `PointerPressed` 中记录源行和起点。
2. `BeginRowDrag` 根据源行和 `SelectedProfiles` 生成 `_dragSourceIndexIds` 快照。
3. `PointerMoved` 根据当前目标行更新块避让动画和浮层位置。
4. `PointerReleased` 调用 `ProfilesViewModel.MoveServersTo(_dragSourceIndexIds, targetItem)`。
5. ViewModel 校验分组类型、目标合法性和故障转移边界。
6. 普通分组调用批量 `ProfileEx.Sort` 重写逻辑；故障转移队列调用批量队列排序逻辑。
7. 成功后刷新节点列表；故障转移队列变更时发布现有状态刷新事件。

## 错误处理

- 源集合为空、目标为空、源或目标在当前列表中找不到时直接返回，不修改排序。
- 源集合去重后只剩一个节点时，可复用现有单节点移动逻辑或走批量逻辑，结果必须与现有行为一致。
- 目标位于源集合内部、源集合首尾跨度内或其它最终顺序不变的位置时，直接返回不做操作。
- 故障转移分组跨队列区拖拽、混合队列源集合、目标不可移动时静默忽略，保持现有拖拽边界风格。

## 测试计划

自动化测试优先覆盖纯逻辑：

- 非连续源集合向下移动后合并为连续块，并保持原相对顺序。
- 非连续源集合向上移动后合并为连续块，并保持原相对顺序。
- 目标位于源集合首尾跨度内时，不产生排序变更，也不产生错误的重复、丢失或乱序。
- 普通单节点拖拽结果与现有测试保持一致。
- 块避让动画函数对向上、向下、多源、无效输入返回预期偏移。
- 故障转移队列批量移动保持队列内部顺序并重写 `FailoverGroupItem.Sort`。
- 故障转移分组中混合队列和非队列源集合不能移动。

手工验证覆盖 Desktop UI：

- 普通分组中 `Ctrl` 多选非连续节点，拖拽后合并为连续块。
- 普通分组中 `Shift` 连续多选节点，向上和向下拖拽都保持块顺序。
- 从未选中节点开始拖拽仍只移动该节点。
- 故障转移开启且队列置顶时，队列节点只能在队列区内批量拖动。

## 代理安全影响评估

本次改动只影响 Desktop 主界面节点列表排序交互和本地排序持久化。它不修改代理模式、Tun、系统代理、路由规则、DNS、订阅、核心组件、Geo/SRS 数据、更新下载、证书、网络请求、本地监听端口或核心配置生成逻辑。

需要关注的安全相关边界是故障转移队列顺序。队列批量排序只允许在既有可移动范围内调整顺序，不应改变队列成员关系，不应把队列节点和非队列节点混排，也不应绕过现有活动故障组刷新逻辑。实现和测试必须覆盖这些边界，避免错误排序导致运行态故障转移顺序与用户预期不一致。

## 非目标

- 不实现跨分组拖拽。
- 不改变节点选择模型。
- 不重写 DataGrid 多选行为。
- 不修改 WPF 版拖拽排序。
- 不改变故障转移队列成员增删逻辑。
